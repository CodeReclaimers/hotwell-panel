**Key decisions** (full rationale in HANDOFF.md "Decisions taken"):
- The session log *is* the replay scenario, built from the log alone rather than
  the original scenario plus a diff. Rejected: merging operator actions into the
  scenario's event list — `Simulator.step()` applies scenario events before
  submitted actions, so a tick carrying both reorders under a naive merge.
- Replay event times are stamped a **half tick early**. Rejected: exact tick
  times — measured accumulated-float drift is −1.089e−9 s at 36000 ticks, past
  the core's 1e-9 firing tolerance, so a late-session action would fire one step
  late and break the hash silently.
- Alarm edges are synthesised by diffing observations, because the core emits a
  `FiredAction` only for non-`alarm` actions and reports a clear as a
  disappearance.
- A FIRST OUT plate separate from the annunciator, because the canonical
  casualty's initiator (`CP1_TRIP:overload`) is a free-form label with no
  protection-table id and so can never light a window.
- Conflicting same-key actions defer to the next tick instead of collapsing.
  Rejected: last-wins — ACK-ALL sends one `alarm.ack` per window and would
  acknowledge exactly one.
- Layout is machine-validated (bounds, 8 px grid, overlaps including gauge bezel
  and label plate, annunciator capacity, full instrument coverage) rather than
  eyeballed. It caught every collision in the first two layout passes.
- `frame.loops` reads controller state off `Simulator.control`. Rejected:
  inferring AUTO/MAN from action echoes — wrong after a reset.
- Instructor station is HTML, not SVG benchboard: it is out-of-fiction (§9).
