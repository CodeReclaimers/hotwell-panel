# Progress — 2026-08-29

## Session: Svelte 5 migration of the panel client (M0)

### Context

PLAN-panel.md §1 was updated (by Alan, in a separate design conversation) to
replace the original locked frontend decision — vanilla JS ES modules, no build
step — with **Svelte 5 + TypeScript + Vite, plain SPA, runes mode forced**.
The vanilla client is P0–P3 complete (95 passed), so this is a stack migration
with a working reference implementation, not greenfield. Agreed decisions:
(1) keep the 16 Chromium browser tests and their `window.panel`/DOM contract;
(2) delete `static/` only after the browser suite passes against the Svelte
client; (3) run-from-checkout — `client/dist` is not wheel-packaged;
(4) the §12.7 manual gate moves to after the migration.

Migration phases: M0 toolchain scaffold + typed hello spine (this entry),
M1 lib/ port + vitest, M2 component port, M3 server cutover + full suite +
delete static/.

### M0 — toolchain scaffold + typed hello spine: complete

**Files created:** `client/package.json`, `client/vite.config.ts`,

the server still serves the vanilla client until M3.

**Key decisions:**

- **Version pins** (exact, no `^`): svelte 5.57.0, @sveltejs/vite-plugin-svelte
  6.2.4, vite 7.3.6, typescript 5.9.3, svelte-check 4.7.6, vitest 4.1.11.
  Rejected the fresh majors: svelte-check 4.x peer range (`^5||^6`) excludes
  TypeScript 7.0; vite-plugin-svelte 7.x requires vite 8 (two-week-old major).
  Peer ranges verified against the registry before choosing.
- **No @types/node** — §1 pins the dev-dep list, so `vite.config.ts` uses no
  node APIs and vitest runs in the `node` environment with no DOM lib (the three
  §12.5 vitest targets are pure logic).
- **`types.ts` mirrors `protocol.py` by hand** (per §4; codegen explicitly
  deferred by the plan). Open-ended server dicts (status, fidelity, options,
  detail) keep index signatures rather than fake precision.
- **Protocol guard is new behavior**, the only intentional behavioral delta of
  the migration: the vanilla client only console.logged the version; §4 requires
  refusal. `protocolMismatch()` (pure, vitest-covered) + `store.fatal` renders a
  full-screen refusal, `conn.stop()` prevents reconnect.
- **Store is a runes class** (`lib/frame.svelte.ts`) with `$state.raw` for
  hello/frame — both are replaced wholesale (frames at 20 Hz), so deep proxying
  is pure overhead; reactivity is at the reference level.
- **`main.ts` stays the composition root** mirroring `main.js`: Connection
  handlers wire into stores; components receive `conn` via props. `window.panel`
  exposure preserved for the browser tests (M0: `store`, `conn`; registries
  join in M1/M2).
- **`conn.handlers` remains public and mutable** — `test_chart_query_reports_
  unknown_signals` swaps `handlers.chart_data` at runtime; dispatch looks up
  handlers at delivery time.

**Key decisions:**

- Machine state is a deep `$state` Record (19 windows; per-window mutation
  stays fine-grained), while `soe.lines` is `$state.raw` replaced wholesale
  per push (≤ 400 entries) — same reference-level reasoning as the frame store.
- The vanilla `paint()` logic became pure `groupClasses`/`windowClasses`
  functions, so vitest pins the exact class strings the Playwright suite
  asserts (`lit`, `flash-fast`, `flash-slow`, `first-out`, `trip`).
- Vanilla semantics preserved exactly, including clear-while-FAST → SLOW
  (not strict ISA-18.1 sequence A; behavior-preservation wins — flagged here
  rather than silently "fixed").
- `events.test.ts` is beyond the three §12.5-mandated vitest targets — cheap
  pure-logic pinning of a ported store, noted as deliberate.

### M2 — component port: complete

**Files created:** 14 components under `client/src/components/` (Plate, Lamp,
Gauge, PistolGrip, Breaker, BoardButton, StationButton, MAStation,
Annunciator, ChartRecorder, SoeLog, AdvisorBezel, Mimic, Instructor),
`lib/registry.ts` (gauge/chart counters for `window.panel`), `lib/chartdata.ts`
(chart_data fan-out so `conn.handlers.chart_data` stays a single swappable
slot). `App.svelte` became the full board shell; `main.ts` gained the
annunciator button handlers (SILENCE / ACK-only-flashing / RESET / held LAMP
TEST), chart dispatch, and `session_exported` capture.

**Key decisions:**

- **`{#key store.hello}` remounts the whole board per hello** — reproducing
  the vanilla client's render-from-scratch semantics on LOAD/RESET exactly
  (recorders re-backfill, grips re-center, instructor selects re-seed).
  Machine `install()` was reordered BEFORE `store.setHello` so the remount
  renders installed state.
- **Faces are `{@html}`-injected inside Gauge per §5.2**, replacing the shared
  `<defs>`+`<use>` scheme. The DOM consequence: 17 placed faces instead of 23
  defs — the one flagged smoke-test assertion change, to be applied in M3
  (assert 23 faces in `hello.gauge_faces` AND 17 in-DOM).
- **Chart pen sample arrays are deliberately not reactive** (mutated at 20 Hz,
  up to thousands of points); only render outputs (path `d` strings, select
  values, axis labels) are `$state`.
- **Mimic stays an opaque hand-authored fragment**: `board.svg?raw` via
  `{@html}`, with one `$effect` toggling `data-pump`/`data-indication`/
  `data-flow` classes — the same contract the vanilla client had.
- **Instructor drawer `open` lives in module-level `$state`** so a LOAD/RESET
  remount doesn't slam the drawer shut.
- svelte-check's 33 warnings were fixed properly rather than suppressed:
  geometry consts became `$derived`; two genuinely-initial captures
  (chart pens/span seed, covered-guard seed) carry `svelte-ignore
  state_referenced_locally` with a rationale comment; clickable SVG groups
  gained Enter/Space keyboard activation (beyond vanilla, behavior-neutral,
  and §6.2 already demanded keyboard grips).
