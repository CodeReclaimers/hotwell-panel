# Progress — 2026-08-29

## Session: Svelte 5 migration of the panel client (M0)

### Context

PLAN-panel.md §1 was updated (by Alan, in a separate design conversation) to
replace the original locked frontend decision — vanilla JS ES modules, no build
step — with **Svelte 5 + TypeScript + Vite, plain SPA, runes mode forced**.
The vanilla client is P0–P3 complete (95 passed), so this is a stack migration
with a working reference implementation, not greenfield. Agreed decisions:
(1) keep the 16 Chromium browser tests and their `window.panel`/DOM contract;
(2) delete `static/` only after the browser suite passes against the Svelte
client; (3) run-from-checkout — `client/dist` is not wheel-packaged;
(4) the §12.7 manual gate moves to after the migration.

Migration phases: M0 toolchain scaffold + typed hello spine (this entry),
M1 lib/ port + vitest, M2 component port, M3 server cutover + full suite +
delete static/.

**Key decisions:**

- **Version pins** (exact, no `^`): svelte 5.57.0, @sveltejs/vite-plugin-svelte
  6.2.4, vite 7.3.6, typescript 5.9.3, svelte-check 4.7.6, vitest 4.1.11.
  Rejected the fresh majors: svelte-check 4.x peer range (`^5||^6`) excludes
  TypeScript 7.0; vite-plugin-svelte 7.x requires vite 8 (two-week-old major).
  Peer ranges verified against the registry before choosing.
- **No @types/node** — §1 pins the dev-dep list, so `vite.config.ts` uses no
  node APIs and vitest runs in the `node` environment with no DOM lib (the three
  §12.5 vitest targets are pure logic).
- **`types.ts` mirrors `protocol.py` by hand** (per §4; codegen explicitly
  deferred by the plan). Open-ended server dicts (status, fidelity, options,
  detail) keep index signatures rather than fake precision.
- **Protocol guard is new behavior**, the only intentional behavioral delta of
  the migration: the vanilla client only console.logged the version; §4 requires
  refusal. `protocolMismatch()` (pure, vitest-covered) + `store.fatal` renders a
  full-screen refusal, `conn.stop()` prevents reconnect.
- **Store is a runes class** (`lib/frame.svelte.ts`) with `$state.raw` for
  hello/frame — both are replaced wholesale (frames at 20 Hz), so deep proxying
  is pure overhead; reactivity is at the reference level.
- **`main.ts` stays the composition root** mirroring `main.js`: Connection
  handlers wire into stores; components receive `conn` via props. `window.panel`
  exposure preserved for the browser tests (M0: `store`, `conn`; registries
  join in M1/M2).
- **`conn.handlers` remains public and mutable** — `test_chart_query_reports_
  unknown_signals` swaps `handlers.chart_data` at runtime; dispatch looks up
  handlers at delivery time.

## Session: hotwell 0.3.0 consumption — station-service pump loads

### Context

Playing the panel, Alan observed that starting condensate/feed pumps does not
change generator load. Diagnosed as core physics (pump motors were only an
ammeter display proxy; `Loads.p_elec` summed the two abstract blocks — the
D10 abstraction, explicitly out of panel scope per §15). Alan chose "core
task now": hotwell 0.3.0 was implemented in `../hotwell` (see that repo's
`progress-20260829.md` and CHANGELOG; commit `9464eb2`). This entry covers
the panel side only.

### Changes

- `pyproject.toml`: `hotwell>=0.3,<0.4`; venv reinstalled (editable).
- `tests/test_casualty_sequence.py`: the two-state **specification** table
  re-pinned to the 0.3.0 core HANDOFF values — DRUM_P_HI +19.9→+19.6,
  HOTWELL_HI +57.2→+57.3, FP1_SUCTION +92.7→+92.8, DRUM_LVL_LOLO
  +127.4→+127.3 (DA_LO, SAFETY_VALVE, DRUM_LVL_LO unchanged); docstring now
  names the regeneration command. The AB+3E **characterization** test passed
  untouched (its loose tolerances absorbed shifts ≤ 0.7 s).
- `HANDOFF.md`: built-against bumped to 0.3.0 `9464eb2` with the panel-facing
  consequences (FP-2 start ≈ +0.3 MW on GEN OUTPUT; CP start +0.02 MW —
  real but below the 0.1 MW meter resolution, ammeter is the cue; 0.2.0
  session logs no longer replay to their recorded hashes); conflict-1 table
  re-measured under both fidelities.
- No client changes: display anchors and §5.1 were preserved by the core's
  gross-output semantics, by design.

### Caught during the bump

- `hotwell.__version__` was hardcoded in the core's `__init__.py` and missed
  by the pyproject bump — the panel venv exposed it immediately
  (rejection-patterns "peripheral references" class). Fixed and amended into
  the core release commit; swept for other stale version strings (the two
  remaining "0.2.0" mentions are historical annotations, correct as-is).
