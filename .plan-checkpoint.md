## Constraints

- **One Python process** — FastAPI serves static + WebSocket; sim in an asyncio task.
  No workers, no broker (§1).
- **Frontend: vanilla JS ES modules + SVG. No build step, no node, no framework** (§1).
- **Panel is a thin animation/input layer** — everything derivable from contracts is
  generated server-side in Python and shipped as SVG/JSON (§1).
- **Sim time authoritative; actions stamped to sim ticks**, queued and applied at the
  next tick boundary exactly as scenario `action` events. Every session reduces to a
  scenario file, replayable bit-identically headlessly. **Contract** (§1, §3.4).
- **Fixed dt = 0.05 s always.** Speed multiplies steps per wall tick, never dt (§1).
- **Display units US customary, period-correct**, panel layer only; hotwell SI contract
  untouched (§1, §5).
- **Panel default fidelity: `drum.model: astrom_bell` + three-element feedwater** (D18).
  Two-state + single-element remain instructor-selectable degraded modes, not bugs (§1).
- **This repository never edits `hotwell`.** §11 is a precursor executed in the hotwell
  repo first and released as 0.2.0. Anything else goes in HANDOFF.md as a proposal (§1).
- Runtime deps: `hotwell>=0.2,<0.3`, `fastapi`, `uvicorn[standard]`. Dev: `pytest`,
  `ruff`, `playwright`. **Nothing else** (§1).
- Frequency meter face **must** span 66 Hz overspeed equivalent (50–70 Hz); do not
  "improve" to 55–65 (§5.1, phase-1 handoff).
- Indicating lamps: **red = running/energized, green = stopped** (power plant
  convention, not traffic-light) (§10).
- **Do not start UI until the §12.2 replay test passes** (§13 P0).
- Files ≲ 300 lines; ruff clean; JSDoc on public JS modules (§14).
- Setpoint adjustment on M/A stations out of scope; fixed setpoints as in core (§6.3, §15).
- Out of scope (§15): agent/LangGraph/any LLM call, content behind advisor bezel, auth,
  multi-user roles, non-localhost, HTTPS, mobile/touch, station-service/blackout
  modeling (D10 stands), sound beyond horn + switch clicks, scoring/eval harness,

## Core-contract findings that shape the design (found during orientation)

1. **Alarm transitions are not in `fired`.** `protection/interlocks.py:90` appends a
   FiredAction only for `a != "alarm"`, so pure-alarm conditions (DRUM_P_HI, DA_LO,
   HOTWELL_HI, DRUM_LVL_LO — most of the §12.6(a) cascade) emit nothing. And
   `alarm_states()` returns only non-CLEAR entries, so a clear is a *disappearance*.
   => The server must diff `obs.alarms` tick-over-tick to synthesize activate/ack/clear
   `event` messages (§4). Getting this wrong fails §12.6(a) with every window dark.
2. **Replay same-tick ordering hole.** `simulator.step()` runs
   `_apply_scenario_events()` BEFORE `apply_actions()`. In replay, operator actions
   become scenario `action` events sorted by `t` among the other events, so a tick
   carrying both an injected event and an operator action can reorder. The canonical
   300 s/312 s pair never collides — §12.2 would pass without covering it. Needs an
   explicit same-tick test case.
3. **Instructor `inject_event` is not an action.** §3.4 records "every applied action";
   injections are scenario *events*. If the session log holds only actions, a
   live-inserted casualty will not replay. Decision required + HANDOFF note.
4. **`set_load` units boundary.** Core takes `p0` in **absolute watts**
   (`p0: 54.0e+6`); §9 says "MW delta". Convert at the instructor edge against current
   `plant.loads.<block>.p0`, with a test. (rejection-patterns.md class.)
5. **`alarm.ack` on a non-ACTIVE id is rejected** by `engine.acknowledge`, so the ACK
   button must send only currently-ACTIVE ids or the SOE fills with spurious rejections.
6. **Canonical first-out `CP1_TRIP:overload` is a `record_external_trip` string, not a
   protection.yaml id** — it has no annunciator window. §12.6(a) wants correct first-out
   visible => needs a dedicated FIRST OUT display path (plate + SOE line).
7. **§5.1 klb/hr anchor arithmetic.** 76.923 kg/s -> 610.3 klb/hr, not the plan's 611.
   Flag the row; do not tune the conversion constant to match.
8. **§11.3 test discriminator.** Under an editable install `Path(__file__).parents[3]`
   still resolves into the repo, so a chdir-to-tmpdir test passes with the OLD code.
   Must assert the accessor's path is under `Path(hotwell.__file__).parent` (or build a
   wheel into a throwaway venv), else the gate cannot fail.
