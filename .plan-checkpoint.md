## Client behaviors that must survive the port (encoded in code, not the plan)

- First-frame needle snap (no fake sweep-up on connect); rAF dt clamp 250 ms.
- ACK sends `alarm.ack` only for currently-FAST windows (core rejects others).
- Manual-trip cover: lift arms for one press, auto-relatches after 4 s.
- FIRST OUT plate separate from annunciator (free-form labels have no window).
- Horn: idempotent start, SILENCE ≠ ACK, mute is instructor-side; audio behind
  one pointerdown unlock. Switch click sound.
- Chart: horizontal time, backfill on load/reassign/span-change, per-pen trim to
  1.05× span, request-id map, unknown-signal warning; pen dropdowns are real
  <select> in foreignObject.
- Annunciator seedFromFrame on first frame only (mid-casualty connects).
- Hello re-renders everything (load/reset send a fresh hello); backfill re-anchors.
- Frames only when sim steps + one push on state-changing instructor cmds (§3.2);
  UI flashers CSS-driven on wall clock.
- Lamp convention red=running / green=stopped / amber=tripped (§10).

## Known test-contract deltas (flag, don't hide)

## Core-contract findings from the original run (still load-bearing)

1. Alarm transitions synthesized server-side by diffing observations (events.py) —
   the client never diffs frames.
2. Session log IS the replay scenario; event times stamped a half tick early.
3. `alarm.ack` on non-ACTIVE id is rejected → ACK button sends only flashing ids.
4. First-out labels (CP1_TRIP:overload, MANUAL_*) are often not protection ids.
5. `set_load` MW-delta→watts converted server-side; log stores resolved absolute.
6. §5.1 steam anchor reads 610 not 611 (0.1 kg/s quantization); pinned in tests.
